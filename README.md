# 号枢

中文名：**号枢** · 前缀 `haoshu` · 端口 **6300 / 11300**

## 骨架

**业务键入枢纽 → 关系进链接 → 属性进卫星（载荷哈希开版）→ 枢纽-链接-卫星互证**

皮：号卡 / 套餐 / 客户。去皮是 Data Vault，不是营业厅办号、不是积分商城。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6300 → 入湖灌样例 → 枢纽/链接/卫星 → 贯验
```

## 贯验孤儿卫星 · 乙口径（当前+历史链）

全局只贯彻一种口径：**同父下任一卫星行（当前或历史非当前）父不可解即孤儿，本轮贯验失败**。
「仅历史孤儿、无当前孤儿」同样判失败；死父键在清理/重挂并重新贯验通过前禁止再开新当前版。

- 扫描：`GET /api/孤儿`、`GET /api/卫星/巡检`、`GET /api/卫星/孤儿`
- 履历：`GET /api/贯验/孤儿`（末次或 `?贯验编号=`）
- 开版闸：`POST /api/卫星/开版`，失败闭、零增量；装载链路共用同一闸
- 夹具：`孤儿-当前`、`孤儿-历史`、`孤儿-失败后开版`（`POST /api/夹具/场景?名=...`）
- 自检：`python3 backend/scripts/孤儿场景自检.py`

## 孤儿扫覆盖戳 · 架构「规」（以现行站规为准）

关键设计取舍全局只贯彻一种，选定**以现行站规为准**。另一可行架构「戳」（以跑次覆盖戳为准：
重跑沿用旧戳范围、改范围须显式新开跑次）本仓不实现。两架构在「先仅当前失败、改站规为
当前+历史再跑」上可区分：**架构「规」重跑即按新范围扫出历史孤儿；架构「戳」会沿用仅当前、
历史继续漏网**（自检 `孤儿-覆盖戳分叉` 钉死该断言）。

钉死规则：

1. 每次贯验都是**新跑次**：跑次号、覆盖范围、孤儿件数摘要、站规版本与结论在**同一写事务**
   内同成败；半截失败整票回滚——禁止「结论已落而覆盖戳空」。
2. 重跑按**最新现行站规**重扫并钉新戳，旧戳不可变、仅作审计；旧戳范围与现行站规分叉时，
   只读核证判失败且禁止沿用旧结论——禁止戳范围与站规分叉仍标通过。
3. 清扫写闸三条件缺一即拒：有戳、戳范围/版本与现行站规互证、戳件数与实时重扫一致；
   **禁止无戳清扫改写正式孤儿处置**，处置单回钉跑次号与戳编号。
4. 开版/装载闸串联覆盖戳互证：分叉态禁止沿用旧结论开新当前。

- 覆盖戳核证（基线所无，只读新接口）：`GET /api/贯验/孤儿覆盖戳/核证`（可 `?戳编号=` / `?跑次号=`）
- 覆盖戳履历：`GET /api/贯验/孤儿覆盖戳`；站规版本履历：`GET /api/站规/版本`
- 站规覆盖变更（仅 `仅当前` / `当前+历史`，变更即开新版本）：`POST /api/站规/孤儿覆盖`
- 孤儿清扫写闸：`POST /api/孤儿/清扫`；处置履历：`GET /api/孤儿/处置`
- 夹具：`孤儿-覆盖戳分叉`（灌历史孤儿再切覆盖）、`孤儿-清扫写闸`（无戳/分叉/漂移拒扫）
- 自检覆盖：半截钉戳回滚、半截清扫回滚、扫贯验与改站规并发（写锁串行，两序均不漏网标通过）
